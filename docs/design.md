# GPT 降智测试 · 设计

状态:已于 2026-10-18 上线(`https://gpt.ziikoo.app`)。决策记录与上线状态见末尾,平台与部署见 [`architecture.md`](architecture.md)。

## 目标

用户有一把中转站的密钥,想知道所买的 GPT 模型是不是原装,没有被换成弱模型。页面给出可核对的结论和证据。

非目标:公开站点榜单、用户自带题目、账号体系、替代控制台。

## 用户与意图

用户嘴上说「智商测试」,心里问的是「我花钱买的模型是真的吗」。

| 谁 | 什么时候来 | 真正的问题 |
| --- | --- | --- |
| 刚买便宜中转站的个人开发者 | 付费前试用,或觉得最近变笨 | 这把 key 是不是被换成了小模型 |
| 给团队选型的技术负责人 | 手上有几家候选 | 哪家能用,能不能留证据 |
| 站长或渠道商 | 自查上游 | 我这条线路会不会被判差 |
| 围观者 | 看到截图 | 好玩,想分享 |

## 交互路径

到达,选题,粘贴,确认花费,等待,读结论,下一步。

| 阶段 | 用户在想什么 | 页面要做到 |
| --- | --- | --- |
| 到达 | 这是啥,我的 key 安全吗 | 表单上方一行摘要,可展开。说清密钥只在每次调用时转发,不存储。测试结果与原始响应保存最近 10 轮,凭同一密钥可查看与删除。建议用限额的测试 key |
| 选题 | 测什么,凭什么 | 勾选题目,每题两行:标题与类型,一句「测什么」;题面、标准答案、复制收在「查看题面」里 |
| 粘贴 | 我不想懂协议 | 站点地址、密钥、模型三项。地址剥掉尾部 `/v1` 与端点路径,保留其余路径前缀(如 OpenRouter 填 `https://openrouter.ai/api/v1` 或 `https://openrouter.ai/api`),密钥去掉 `Bearer ` 与空白,模型默认 `gpt-6-astra`;站点与密钥填好后自动加载模型列表,模型字段可从下拉里选,也可手打 |
| 确认花费 | 会不会烧我的钱 | 写明已选题数与最多调用次数,差的站点第一关就停 |
| 等待 | 卡住了吗 | 每题结论卡内一条四关阶梯,逐次小点,可取消。离开页面前提示 |
| 读结论 | 凭什么这么判 | 结论先行,一句诊断,逐次明细默认折叠(正确与否、reasoning tokens、回答片段、响应 ID 形态) |
| 下一步 | 然后呢 | 再测、换模型、也测另一通道 |

不放心粘贴密钥的用户,可以复制题面到自己的客户端手动测。手动结果不在本站评分。

页面名用「GPT 降智测试」。不使用「可上架」,那是运营内部用语。

## 页面结构

单页,路由只有 `/`。栅格体系:容器最宽 1200px,水平内边距 `clamp(16px, 4vw, 32px)`,12 列,三个断点(小于 720px 单列、720 到 1039px、1040px 及以上)。设计令牌用 CSS 变量,浅色深色各一套,间距以 4px 为基准。

```
页头      标题、一句话说明、锚点导航
页签      实时测试、HTML 生成、持续监测;HTML 生成见「生成器题 `pelican-svg`」
监测页签  一句说明加工具条(添加站点、看板链接、卡片/列表切换)、区块级图例、卡片栅格或列表
隐私说明  一行摘要,可展开看四条详情
站点与密钥 站点、密钥、模型(字段带下拉)加开始按钮一行(宽屏),720 到 1039px 两行,窄屏单列   (全宽)
结果区    总评主视觉与再测动作、每题结论卡(阶梯、一句诊断、折叠的逐次明细)、输入用量核对 (全宽,有轮次时出现并滚动到此)
选题      多选清单,默认只选 thibault,题面可展开、可复制,未校准提示在区块顶部一句;标题行右侧「自定义题」按钮,点开才渲染表单   (全宽)
历史      凭站点和密钥取回最近 10 轮              (全宽)
API 说明  默认折叠,含接口约定、分关规则、curl 示例、限额   (全宽)
```

遵循的约束:

- 生成题在标题旁标「每轮随机生成」,按钮叫「查看示例题面」「复制示例题面」,下方一行说明题面每轮会变。页面每轮抽一个 seed,本轮全部调用都带它,「重新测试」和「也测另一协议」各抽新 seed。
- 不用 KPI 卡片、卡片套卡片、图标块。监测卡片是顶层容器,内部不再嵌套卡片。
- 回答内容当纯文本渲染,配严格 CSP:`style-src 'self'`,所以页面里**不能有任何内联 style 属性**,动态外观只能靠 class、`data-*` 加 CSS 选择器或 SVG 属性。页面不依赖外部脚本。
- 进度点和状态用「颜色加形状」双重编码,折线图两条线一实一虚,色觉友好。
- 手机宽度(375 到 430px)不出现横向滚动,深色模式可用,键盘可操作。
- `data-testid` 是 e2e 的契约:监测卡片的 testid 用 `custom-<id>-…` 前缀,每张卡片唯一,因为 Playwright 的 `getByTestId` 遇到同名多个会报严格模式错误。

## 总评与结论词汇

| 总评 | 条件 |
| --- | --- |
| 全部通过 | 所选题目都通过 |
| 部分通过 | 至少一题通过、至少一题未通过 |
| 未通过 | 所选题目都未通过 |
| 无法测试 | 站点不可达、401、限流等,与模型质量无关 |

不在 v1 里把多题组合推断成「后端属于哪一族」,没有数据支撑。

结果卡必须写明「只代表此刻」。已观测到同一站点一天内翻转。

## 题库

一道题就是一份数据文件,放在 `questions/`,构建时打进 Worker。加题等于加文件加测试,不改页面与接口代码。

```ts
type QuestionManifest = {
  id: string                       // 接口枚举值
  version: number                  // 改题面或评分就加 1
  status: "active" | "retired"
  title: string
  measures: string                 // 一句话说明这题测什么
  kind: "knowledge" | "reasoning" | "metrics"
  prompt: string                   // 展示给用户,也是实际发出的文本,同一字段
  scorer?:                         // metrics 类型没有评分器
    | { type: "yes_no"; expected: "YES" | "NO" }
    | { type: "numbers"; expected: string[] }
    | { type: "final_numbers"; expected: string[] }   // 只读最后一行「答案:」,按顺序逐个比对
    | { type: "contains"; expected: string }
    | { type: "svg_animation" }                       // 完整 HTML 里有 SVG 与动画,见「生成器题 `pelican-svg`」
  generator?: "candy" | "pelican"  // 生成器题:题面与评分由服务端按 seed 生成
  inWatchRotation?: boolean        // false 时不进监测轮转,缺省为 true
  expectedLabel: string            // 给人看的答案说明,评分不用它
  defaultEffort?: "low" | "medium" | "high" | "xhigh"
  calibratedModels: string[]
  failureHint: string              // 本题淘汰时的诊断句
}
```

可扩展:新题、新评分类型(评分器表里加函数与测试)、题的上下线、随请求携带的单次自定义题(见「自定义题」节)。
不可扩展:自定义题入库或入清单、每题独立阈值、运行时热加载。

评分器用按类型取函数的表,不用分支堆叠。

`metrics` 是仅度量题,只采集指标,不评分,不走四关梯度,顺序执行不并发。首期只留类型口子,不上题。第一道预期是「长前缀」题,用来算缓存命中率,见「指标」一节。

### 首期两题

| 项 | `candy` | `thibault` |
| --- | --- | --- |
| 类型 | 推理 | 知识 |
| 评分 | `numbers`,21、9、12 须同时出现 | `yes_no`,期望 YES |
| 默认强度 | `low` | 不指定 |
| 标准答案 | 21 颗(9 颗圆形 + 12 颗五角星) | Yes |
| 校准模型 | 只有 `gpt-6-astra` | 只有 `gpt-6-astra` |

题面原文如下,实现时原样迁入清单。糖果题面含制表符与换行,复制与发送必须逐字节一致。

`thibault`

```
don't search the internet, do you know Thibault Sottiaux on X. answer yes or no
```

`candy`(列之间是制表符)

```
在一个黑色的袋子里放有三种口味的糖果：苹果味、桃子味、西瓜味。每种口味又各有两种形状：圆形和五角星形；两种形状可通过手感区分，但糖果的口味无法通过手感区分。

袋中糖果数量如下：
形状	苹果味	桃子味	西瓜味
圆形	7	9	8
五角星形	7	6	4

你需要在活动前决定从袋中摸出多少颗糖果，以及分别摸多少颗圆形、多少颗五角星形糖果。

要求：无论实际摸到的口味组合如何，手中都必须保证存在以下两种配对中的至少一种：
1. 一颗圆形苹果味糖果，和一颗五角星形桃子味糖果；
2. 一颗圆形桃子味糖果，和一颗五角星形苹果味糖果。

问：至少需要摸出多少颗糖果，才能保证满足要求？
```

已知风险:

- 题面只问总数。只回答「21」的正确回答会被判错。原装模型通常会展开推导,`low` 强度下偶尔简短的情况没有数据。结果明细在判错时显示缺了哪些数字。
- 题面公开意味着站长可以预置答案。应对只有换题并升 `version`,页面标出版本。
- 加长版 Thibault(绕开短输入拦截)首期不上。短输入被拦时,诊断必须说明是被拦截,不能写成模型差。

### 人设题 `ciallo`

2026-10-22 加入。题面只有一行 `ciallo`。原厂模型带有角色扮演人设,回复里出现 `Ciallo`(通常是 `Ciallo～(∠・ω< )⌒☆` 加一句中文);被替换或降智的模型常回复英文或通用句子。评分 `contains`,回答含 `Ciallo`(区分大小写)即答对。

- 题面短,单次调用便宜,适合作为快速检查。
- 题面公开,站长可预置 `Ciallo` 应答。应对与 thibault 相同:换题并升 `version`。
- 未在真实原厂接口上校准,`calibratedModels` 为空,页面按「此模型未校准,结果仅供参考」显示。

### 生成器题 `candy-var`

站点可以对公开的固定题预置答案。`candy-var` 每轮换一道同构的糖果题,物品、属性与数字都从封闭词表和随机数里取,预置答案就失效。固定的 `candy` 保留作对照。

- 清单里没有 `prompt.txt`,只写 `generator: "candy"`。题面与评分器由 `src/shared/candy-gen.ts` 按 seed 生成,求解器算出总数和两个数量。
- 评分 `final_numbers`:最后一行「答案:总数=?,X=?,Y=?」的三个数字须按顺序全部答对。判错时 note 为 `want 24/11/13 got 25/12/13`。
- seed 是 0 到 4294967295 的整数。一轮用一个 seed,由页面选定;监测和命令行不带 seed 时用 0。题目清单展示的题面就是 seed 0 的实例。
- seed 随每次调用落库,原始数据里能看到。同一 seed 总是生成同一道题。
- 生成器或求解器一改,同一 seed 的题就变了,题的 `version` 加 1。

### 生成器题 `pelican-svg`

2026-10-25 加入。题面要模型直接写出一个 HTML,内容是用 SVG 画的一只鸟在某个场景里骑自行车的 2D 动画。这题测模型能否一次写完一段长而完整的代码。2026-10-26 起,页面只在「HTML 生成」页签里对这题单次调用,实时测试的选题清单不再列出它。

- 清单只写 `generator: "pelican"` 与 `html: true`。`html` 标记表示回答是一页 HTML:探针从回答里取出页面作为 `artifact` 返回,取法见本节「取页面」;不带 `runId` 时用长回答上限。带这个标记的题称 HTML 题,目前只有这一题。
- 题面由 `src/shared/pelican-gen.ts` 按 seed 生成。
- 鸟来自封闭词表 `BIRDS`(50 种),场景来自封闭词表 `SCENES`(50 个),交通工具固定为自行车(2026-10-27 维护者决定)。组合序号是 `seed % 2500`:鸟是 `序号 % 50`,场景是 `序号 / 50` 取整。站点无法只预置一个答案。seed 范围与 `candy-var` 相同。
- seed 0 是鹈鹕在落日下的海边木栈道。题面原文如下:

```
创建一个HTML，内容是用SVG绘制一只鹈鹕骑自行车的2D动画，场景是落日下的海边木栈道，你不能进行任何测试、禁止调用skills、禁止网络检索，直接生成
```

- 评分 `svg_animation`,对完整回答不区分大小写检查四部分:
  1. `html`:含 `<!doctype html` 或 `<html`。
  2. `svg`:含 `<svg`。
  3. `animation`:含 `<animate`、`@keyframes`、`requestAnimationFrame`、`.animate(` 之一。
  4. `complete`:同时含 `</svg>` 与 `</html>`,没写完的回答答错。
- 四部分全有,note 为 `ok`。否则 note 为 `missing [...]`,只列缺的部分。HTML 前后的代码块标记与说明文字不影响评分。
- `inWatchRotation` 为 `false`,不进监测轮转。每次调用都生成一段长 HTML,放进轮转会每隔几次监测调用就花掉用户密钥的一大段额度。
- 成本:回答很长。页面只调用一次,不分关,不带 `runId`,所以不进历史。接口仍接受带 `runId` 的分关调用,脚本跑满四关是 31 次。
- 「HTML 生成」页签:站点、密钥、模型、协议、推理强度(不指定、low、medium、high、xhigh)加「生成一次」按钮,调用中可取消。调用带 `progress: true`:调用中显示倒计时圆环(从本次超时倒数)、当前阶段(等站点响应、等首字、模型正在推理、正在接收回答)、已用时间、已收到的回答字符数和最近一次收到站点数据的时间,不显示回答原文(2026-10-27 维护者要求)。站点发出推理开始的信号后,首字前的阶段显示模型正在推理。信号是 Anthropic 的 `thinking` 块、responses 的 `reasoning` 项或 chat 的 `reasoning_content`。有的站点推理时不发推理内容,只每隔几秒发一次心跳,心跳也算收到数据,所以最近一次收到站点数据的时间能说明连接还在(2026-10-28 维护者同意)。每次调用随机抽一个 seed 出这题,题面不能自己写(2026-10-27 维护者决定)。从点「生成一次」起,表单下方完整显示本次题面,旁边的图标按钮一键复制;成功、失败都保留,取消后清除(2026-10-27 维护者要求)。页签不判对错,由用户播放后自己判断(2026-10-27 维护者决定):成功时只显示总耗时、首字耗时和 token 数,失败时显示原因。token 数在站点给出推理 token 数时分成推理 token 数与回答 token 数(输出 token 数减推理 token 数),没给时只显示输出 token 数(含推理)(2026-10-27 维护者批准)。回答里没有 HTML 页面时,另显示回答片段,并提示不能播放。页面切走或刷新,结果即失。
- 上限:不带 `runId` 的 HTML 题调用,读取上限 8MB,超时 900 秒。原因:流式 HTML 每个 token 一个事件,约 200 字节,完整页面会超过 256KB;xhigh 要先推理 5 分钟以上。读取上限不再往上加:解析时内存峰值约为响应的 6 倍,Worker 一个 isolate 只有 128MB。带 `runId` 的调用仍是 256KB 与 120 秒,存储上限不变。
- 播放:探针接口对 HTML 题另返回 `artifact: { html, ending }`。`artifact` 不入库,也不进历史。
- 取页面:Worker 只看回答,不看题面。这一步只决定能不能播放,不判对错(2026-10-27 维护者批准)。
  1. 标记都不区分大小写。起点是最后一个 `<html`。它前面最近的 `<!doctype html` 与它之间没有 `</html>` 时,这个 doctype 属于同一页,起点前移到 doctype。回答里没有 `<html` 时,起点是最后一个 `<!doctype html`。取最后一份,因为边想边写的模型会先写一份骨架页面,再写正式页面。
  2. 取到其后最后一个 `</html>` 为止,`ending` 为 `closed`。没有 `</html>` 时取到回答末尾:读取上限截断了响应时 `ending` 为 `truncated`,否则为 `unclosed`。这样去掉代码块标记与前后的说明文字。
  3. 两个标记都没有、但有 `<svg` 时,`html` 是去掉首尾空白的整段回答。片段里可能有 `<svg>` 外的 `<script>` 与 `<style>`,所以不裁。读取上限截断了响应时 `ending` 为 `truncated`,否则为 `closed`。
  4. 三个标记都没有时,不返回 `artifact`。页面不显示「播放动画」,只显示 `answer` 的前 70 字。
- `ending` 不是 `closed` 时,页面提示页面不完整。`truncated` 提示站点响应超过 8MB 读取上限、回答被截断;`unclosed` 提示回答在页面写到 `</html>` 之前就结束了,可能是站点限制了输出长度。
- 有 `artifact` 时,「HTML 生成」页签的结果里有「播放动画」「复制 HTML」「下载 HTML」按钮和折叠的「查看 HTML」。源码只按文本显示。按下「播放动画」后,弹窗里的沙箱 iframe 载入 `/api/frame`,页面再把 `artifact.html` 发给它运行。规则见「安全边界」的「播放动画」。
- 「下载 HTML」在浏览器里把 `artifact.html` 存成文件,不经过服务器。文件名是 `<模型名>-<年月日>-<时分秒>.html`,时间取生成完成的本机时间,模型名里字母、数字、`.`、`_`、`-` 以外的字符换成 `-`。文件开头加 UTF-8 BOM,因为沙箱总按 UTF-8 解码,没写 charset 的页面在本机打开时也要按 UTF-8 解码。规则见「安全边界」的「下载 HTML」。
- 除 HTML 题外,本站从不渲染站点返回的 HTML,只按文本显示。
- 题面模板或词表一改,同一 seed 的题就变了,题的 `version` 加 1。

### 自定义题

2026-10-23 授权加入。用户自带题面与评分规则,对本轮站点做单次测试。与题库题的根本区别是:自定义题不进入题库数组 `QUESTIONS`,没有题库 id 与 `version`,当次调用即抛弃。

```ts
type CustomQuestion = {
  prompt: string                  // 1 到 2000 个 Unicode 码位
  scorer:
    | { type: "yes_no"; expected: "YES" | "NO" }
    | { type: "contains"; expected: string }   // 1 到 500 个码位,区分大小写
}
```

- `/api/probe` 增加可选对象字段 `custom`。给 `custom` 就不能再给 `question`与 `seed`;两个都给或都不给返回 400。`kind` 固定为 `knowledge`,`effort` 沿用请求值或默认空,不接受 `defaultEffort`。
- 评分发生在 Worker,与题库题走同一张评分器表。`questionId` 记为 `custom`,`questionVersion` 记为 0。
- 自定义题不持久化:无 `runId`、不写 `Target` 对象、不进历史、不进 `/api/questions` 清单、不参与监测轮转。`answer` 仍只回前 70 字,完整回答不保存,页面刷新即失。
- 自定义题与题库题共用同一套限速(IP、主机、每轮上限)与地址校验,滥用面与题库题相同。
- 日志规则不变:自定义题的 `question` 字段记 `custom`,不记题面。

风险与对策:

- 本站可被当作任意 prompt 的转发端点。对策:题面 2000 码位上限、评分规则 500 码位上限、同一限速、单次调用即抛弃。不做逐内容审核,超限与滥用靠限速兜底。
- 用户把密钥写进自己的题面。密钥经本站发出再被站点回显,不落库所以无泄露面,但页面提示文案提醒不要在题面里写密钥。

## 分关规则

每道题单独分关:各关的调用数是 1、5、10、15,通过所需的答对数是 1、4、9、14。任何一关未通过,该题停止。全部低空过关总分 28/31,约 90.3%。

- 每关内并发 3 到 5。某关已不可能达标时立即停掉本关剩余调用。
- 单次调用最多重试 3 次,连续 3 次无有效响应判「无法测试」。
- 每次探针自设 120 秒超时(不带 `runId` 的 HTML 题是 900 秒),超时作为探针结果返回。
- 梯度逻辑在页面脚本里,规则写入页面的 API 说明,脚本调用方自己循环。
- 每次探针带 `runId`、关卡号和序号。一轮的结论不单独存,读取时由调用序列用同一个共享函数算出。

## 架构

独立小 Worker 加静态页面,同域名。不并入 `zhikou-ai-dashboard`。

```
浏览器(持有密钥,驱动梯度)
   │ 每次探针一个请求,密钥在请求体里
   ▼
POST /api/probe   (Worker,匿名,限速)
   │ 校验目标 → 代发一次 → 评分
   ▼
中转站 /v1/responses、/v1/chat/completions 或 /v1/messages
```

为什么服务端代发:预检测试中,官方接口放行跨域,一家中转站对预检返回 403 且无 CORS 头。样本只有一家中转站,不能推广,但足以说明浏览器直连不可靠。代价是放弃「密钥不出浏览器」。

为什么独立 Worker:代发用户给的 URL 不应与财务、控制库绑定同进程。部署节奏独立。日志策略可逐行审计。

平台事实(Cloudflare 文档):HTTP 请求在客户端保持连接时墙钟时间无上限,单个子请求无固定时限。

分工:

| 位置 | 负责 |
| --- | --- |
| 服务端 | 题库、评分、代发、流式计时、抽取 reasoning tokens 与响应 ID 形态、地址校验、限速、持久化与脱敏 |
| 前端 | 四关阈值、并发、取消、进度、结论文案 |

协议探测不另设接口:第 1 关两路并发发一次,哪路返回有效答案用哪路,都通或都不通时用第一路。模型名含 `claude`(不分大小写)时两路是 `anthropic` 与 `chat`,否则是 `responses` 与 `chat`。「也测另一协议」作为结果后的按钮,换成同一对里的另一路,默认不翻倍花费。

Anthropic 协议(2026-10-27 维护者授权):

- 请求 `POST /v1/messages`。密钥放在请求头 `x-api-key`,另带 `anthropic-version: 2023-06-01`,不带 `Authorization`。
- 请求体固定 `max_tokens: 32000`,这个接口要求必填。32000 适合 Opus 4 以后的 Claude 模型,也够写完一页 HTML。
- 调用方给了推理强度时,请求体带 `thinking: { type: "adaptive" }` 与 `output_config: { effort }`。题的默认推理强度不用于这个协议:它按 OpenAI 推理模型设定,而 4.6 以前的 Claude 模型拒绝自适应思考。
- 回答只取 `text_delta`,不取 `thinking_delta`。用量合并 `message_start` 与 `message_delta` 两处。输入 token 数是 `input_tokens`、`cache_read_input_tokens`、`cache_creation_input_tokens` 之和,缓存 token 数是 `cache_read_input_tokens`。思考 token 不单独计数,推理 token 数为空,`message_delta` 的 `output_tokens` 记为含思考的输出 token 数。响应 ID 形如 `msg_...`,形态记为 `other`。
- 有协议选择的表单(「HTML 生成」、自定义题、添加监测)按模型名给默认值:模型名含 `claude` 时切到 `anthropic`;改成别的模型名时,`anthropic` 退回 `responses`,手选的 `chat` 保持。模型列表不用来判断协议:本站用 `Authorization` 请求 `/v1/models`,站点按 OpenAI 格式返回,看不出是否支持 `/v1/messages`。

## 持久化

每个 [站点 × 密钥] 对象保存最近 10 轮测试,以及这些轮次里全部调用的原始数据。一轮指点一次「开始」跑完的整轮,含所选各题的全部调用。

- **对象标识。** `HMAC-SHA256(pepper, 归一化站点 + "\n" + 密钥)`。归一化站点是小写主机名加端口,加上剥掉尾部 `/v1` 与端点路径后剩余的路径前缀(无前缀时与裸主机一致,存量对象 id 不变)。库里只有指纹,没有密钥,也不存密钥尾号。模型与协议是调用的维度,不进标识。
- **存储。** Durable Objects 的 SQLite 后端,每个对象一个实例。保留最近 10 轮是一条删除语句。标识由密钥派生,不存在可枚举的全局表。
- **访问。** 没有账号。读取与删除都必须出示同一站点和同一密钥。
- **pepper。** Worker 秘密。换掉它会让全部历史对象失联,所以不轮换,需妥善备份。
- **保留期。** 闲置 90 天后由闹钟触发清空,每次写入重置闹钟。
- **持久化的前提。** 请求带 `runId`。不带 `runId` 的匿名脚本调用保持无状态,不写存储。
- **上限。** 每轮最多 200 次调用,超出返回 429。单次调用的原始数据上限 256KB,超出标记为被截断。「所有原始数据」指上限内的全部。
- **新对象的建立。** 必须由首个有效响应触发。已存在的对象记录全部结果,含失败。这样随机密钥与不可达主机造不出对象。
- **脱敏。** 所有入库文本在写入前必须把完整密钥,以及 `Bearer ` 加密钥的形式替换掉,因为站点可能在报错里回显密钥。这条必须有测试。

每次调用保存的字段:

```
runId、题 id 与版本、seed(固定题为 null)、关卡、序号、开始时间
协议、模型、推理强度、是否流式
HTTP 状态、错误类别
耗时标记(ttfbMs、firstEventMs、ttftMs、totalMs)
usage 原文
原始响应头(去掉 set-cookie)
原始响应体,流式则为带相对到达时间的事件序列
是否被截断
```

## 指标

| 指标 | 定义 | 对探针的要求 |
| --- | --- | --- |
| 总时延 | 发出请求到响应读完 | 无 |
| TTFB | 响应头到达时刻 | 无 |
| TTFT | 第一个非空文本增量的到达时刻 | 必须流式 |
| 吞吐 | 输出 token 数除以首字到结束的时长 | 必须流式 |
| 缓存命中率 | `cached_tokens / prompt_tokens`,token 口径 | 需要足够长的重复前缀 |
| 推理 token 数、输出 token 数、响应 ID 形态 | 来自 usage 与响应;输出 token 数只回给调用方,不落库 | 无 |
| 各题通过率、成功率 | 由调用序列计算 | 无 |

- 探针使用流式请求,聊天协议请求在末尾带回用量。Anthropic 协议的用量见「架构」节的「Anthropic 协议」。字段与选项名来自对 OpenAI 接口的了解,实现时先核对官方文档。
- 首字时延 TTFT 是首个非空文本增量到达边缘的时刻,即「从边缘看到的首字」。响应是 SSE 就一律记录它,不再按到达节奏猜测是否被缓冲:短答案的增量与完成事件常在同一个网络块里到达,按节奏判断会把它们全部误判成非流式。站点缓冲了流时 TTFT 本来就应该很晚。站点忽略流式参数、返回整块 JSON 时,`streamed` 为 false,TTFT 记为空,不编数。
- 原始数据以「事件加相对到达时间」存储,将来任何指标都能重算。
- 时延是从 Cloudflare 边缘到站点的,不是用户本机到站点的。结果里要说明。
- 糖果与 Thibault 题面都很短,在原装接口上缓存命中大概率为零,算出的命中率没有意义。缓存命中率由后续的「长前缀」仅度量题承担。该题固定一段超过缓存阈值的静态前缀,顺序发多次,第一次预热,其余看命中。阈值数值实现时核对官方文档。
- 改成流式后,此前非流式脚本得到的校准结论不再适用,P1 的校准检查要重做。

### 输入用量核对

结果区末尾有一个默认折叠的「输入用量核对（参考）」,只在页面里计算,不改接口,不多发调用。每题取本轮所选协议下有效调用的输入 token 数中位数(来自 usage 的 `input_tokens` 或 `prompt_tokens`;Anthropic 协议另加两项缓存 token),出两条参考发现。逻辑在 `src/web/prompt-usage.ts`。

- 全局注入:thibault 的中位数大于 `OVERHEAD_LIMIT_TOKENS = 50` 就报。题面是 79 个英文字符,原装接口算上消息格式约 20 到 35 个 token。它短、是英文、各代分词器的结果都稳定,所以是最准的量具。站点给每次调用都加了内容,这里会看到。
- 定向注入:`candy` 与 `candy-var` 同一模板,原装接口上每字 token 数应接近。`candy` 的每字 token 数比 `candy-var` 多出 `TARGETED_RATIO = 0.25` 以上就报。`candy-var` 的字数按本轮 seed 生成的题面计算。只报这一个方向。站点只在公开原题上加内容,这里会看到。
- 两个阈值都没有用真实站点校准,页面写明是参考指标。
- 盲区:站点只给它认得的题面加内容,而这些题本轮没选,就看不到。
- mock 的 `mock-inject-candy` 只给原题加 300,`mock-inject-all` 每次调用加 200,两者都答错,e2e 只跑第 1 关。

## 监测

监测只有一个类型:持续监测,由服务端执行。页面分三个页签:`#live` 实时测试(一次完整的批量测试,行为不变),`#html` HTML 生成(见「生成器题 `pelican-svg`」),`#watch` 持续监测,默认实时测试。实时测试与 HTML 生成在切走时只隐藏不卸载,进行中的调用、表单与结果都保留;持续监测会定时刷新,只在显示时挂载。2026-10-22 去掉了浏览器端监测(页面打开期间由浏览器驱动、`gpt.monitors.v1` 本地存储),原因是它测不到页面关闭后的表现,而用户要的正是持续采集。更早的 2026-10-18 还去掉过运营方网关的服务端「官方监测」(定时触发、`Monitor` Durable Object、`GET /api/monitor`、`GAOXIN_KEY` 秘密)。

每个站点一张卡片,展示内容见下表。

| 项 | 内容 |
| --- | --- |
| 样本窗口 | 档位不由单个半小时格单独决定。每一格的档位,和卡片的总状态,都取一段最近 60 分钟的样本:格的档位取截至该格结束的 60 分钟,总状态取截至现在的 60 分钟。格里显示的调用数、失败数、答错数仍然是这半小时自己的,悬停详情里另外给出"判定依据"的样本数。原因:每 5 分钟探测时半小时格只有约 6 个样本,真实答错率落在 10% 到 20% 之间时,单格结果接近掷骰子,60 分钟窗口把样本数翻倍。每格窗口的样本数少于 10 个时不判档。间隔长时窗口拉长到 10 个间隔,30 分钟间隔取 300 分钟,所以长间隔也能判档 |
| 档位 | 按原因分开,先判先得。窗口内失败率达到 20% 为故障。答错率达到 20% 为降智。失败率达到 5% 为不稳定。答错率在 10% 到 20% 之间(不含 10%、不含 20%)为基本正常,浅绿。答错率不超过 10%(正确率不低于 90%)为运行正常,绿。窗口内样本少于 10 个为调用数不足。无样本为暂无数据。降智是重点关注项,所以排在不稳定之前。阈值是初值,不是实测 |
| 档位颜色 | 运行正常深绿 `#15803d`,基本正常浅绿 `#65a30d`,降智洋红 `#c026d3`,不稳定琥珀 `#e08a00`,故障红 `#b91c1c`,调用数不足蓝,暂无数据灰(亮色模式;深色模式各有对应色)。原因不同,色相就不同:失败系是琥珀到红,答错系是浅绿到洋红。琥珀的填充色 `--warn` 与文字色 `--warn-text` 分开,文字色要满足对比度,偏深 |
| 状态语义 | 整页所有状态(调用点、结论、总评、监测档位、卡片提示)的颜色只在 `src/web/styles.css` 的「语义表」里映射一次:状态属性值(`data-state`、`data-status`、`data-kind`)对应到 ok、fair、quality、warn、bad、info、中性七种语气,组件只读 `--tone`(填充)和 `--tone-text`(文字)。同一语义在整页同色:调用失败、监测不稳定、结论部分通过或不可用都是琥珀,答错对应的监测降智是洋红,监测故障、结论未通过是红,进行中与调用数不足都是蓝 |
| 总状态 | 取截至现在的最近 60 分钟样本的档位;最新样本超过 10 分钟没有更新则为暂无数据。刚添加的卡片显示样本不足,直到攒够 10 个样本 |
| 展示 | 总状态徽标(运行正常、基本正常、降智、不稳定、故障、调用数不足、暂无数据)、站点与间隔与最近一次调用时间、24 小时可用率与答对率与总耗时中位数、48 格分段状态条(可聚焦,悬停看详情)加时间刻度、图例与悬停提示在区块级只出现一次、手写 SVG 折线图(每格总耗时与首字耗时的中位数,一实一虚;不足 2 格有耗时数据时显示空态文案)、默认折叠的数据表(只列有调用的半小时格,最新在前,含调用数、失败数、答错数和两个耗时中位数,时间带日期) |

### 持续监测

用户添加站点与密钥,同意本站加密保存密钥后,由服务端按所选间隔持续调用。页面关闭后监测继续。

| 项 | 内容 |
| --- | --- |
| 谁来探测 | 服务端。每个监测是一个 `Watch` Durable Object,闹钟按间隔触发,题按序号在这个监测选中的题之间轮换,间隔 1、5、10 或 30 分钟,默认 5 分钟。2026-10-28 之前建的监测可能是 15 分钟,继续按 15 分钟运行 |
| 题目 | 添加时选,可选的是 `inWatchRotation` 不为 `false` 的题,默认全选,至少选一道。按题库顺序轮换,与勾选顺序无关。建好后可以修改,见「修改」一行。卡片的元信息列出选中的题 id。早于选题功能建的监测没有存题目,按全部可选题轮换。选中的题以后下线时,轮换跳过它;全部下线时这个监测不再出样本(2026-10-27 维护者要求) |
| 修改 | 卡片与列表行的修改按钮打开表单,可改题目(单选或多选,至少一道)与间隔,经 `/api/watch/update` 保存。别名、模型、协议、密钥不能改。改短间隔时,已排好的下一轮提前到「现在加新间隔」;改长间隔时,已排好的那一轮照常进行,之后按新间隔。轮换序号不清零,下一轮取新题目里序号对应的题。15 分钟的旧监测在表单里仍列出 15,只改题目时不发间隔,间隔保持不变(2026-10-28 维护者要求) |
| 密钥 | 提交后用 AES-GCM 加密存进 `Watch` 对象,密钥是 SHA-256(WATCH_ENC_KEY)。WATCH_ENC_KEY 不可轮换。浏览器只存服务器签发的看板码(board,16 字节 base64url,22 字符),存 `localStorage` 键 `gpt.board.v1`;密钥本身从不进浏览器存储、URL、DOM |
| 看板码 | 一个看板聚合多个 watch 令牌,最多 30 个。看板码由服务端签发并加密存储令牌列表。浏览器迁移旧版 `gpt.watch.v1`(令牌数组)时,调用 `/api/board/adopt` 并删除旧键。看板链接走 URL fragment(`#watch/b=<看板码>`),不发给服务器 |
| 同意 | 添加表单必须勾选「我同意本站加密保存这把密钥」,否则不提交 |
| 上限 | 全站最多 200 个 watch,一个看板最多 30 个,超出返回 429 `watch_limit`。不按 IP 限制 |
| 闲置清除 | Watch:每次查看、暂停、继续、修改都把过期时间推到 7 天后;7 天无人查看自动删除密钥与样本。Board:每次读写把 alarm 推到 7 天后,闲置自动删除 |
| 失败处理 | 服务端只重试超时、站点报错、返回无效内容;连续 5 次 unauthorized 转为 bad_key 状态,界面提示删除后重新添加;添加时首调 unauthorized 直接拒绝,不建卡片 |
| 别名 | 可选,最多 40 字符,用来区分同一站点的不同通道 |
| 刷新或重开 | 卡片凭 localStorage 里的看板码经 `/api/board/view` 批量读取,样本与状态来自服务器 |
| 顺序 | 卡片顺序存在看板里,置顶、上移、下移都是改看板的令牌顺序,刷新与换设备保持;提交的排列与看板现有令牌不一致时返回 409,页面回到原顺序并提示 |
| 列表排序 | 列表视图点站点、状态、可用率、答对率、总耗时中位数的表头,依次是升序、降序、回到看板顺序。排序只改本页显示,不改看板顺序,不存储,切回卡片后清除。排序时隐藏置顶、上移、下移。状态按故障、不稳定、降智、基本正常、运行正常排,升序时和可用率、答对率一样最差的在前。读取中、读取失败、没有数值的行两个方向都排在最后 |
| 关闭页面 | 监测继续。这是本功能的目的 |
| 删除 | 删除卡片立即清空服务器上的密钥、样本与注册表行。看板由下次 view 自动清理已删除的令牌 |
| 换机器 | 点「看板链接」,复制链接到新设备。新设备自动载入全部面板 |
| 重置看板码 | 旧码立即失效,生成新码,监测本身不受影响。用于码已泄露或发错地方的情况 |

**为什么做服务端监测。** 浏览器监测测不到页面关闭后的表现,而持续采集正是用户要的。此前「不做服务端常驻监测」一节写下的底线全部满足:密钥加密存储并凭随机令牌读取与删除、所有者与全局上限、间隔不低于 5 分钟、7 天无人访问自动清除,隐私说明同步改写。2026-10-28 维护者把最短间隔降到 1 分钟,见决策记录「监测修改与 1 分钟间隔」。

- 站点自身的失败用 200 加 `ok:false`,调用方能区分「站点出问题」和「我们出问题」。
- 不提供跨域头。浏览器里的第三方网页不能调用,脚本和命令行不受影响。
- 探针接口的 `answer` 只返回前 70 字。完整回答在历史接口的原始数据里。例外是 HTML 题 `pelican-svg`:`artifact.html` 带从回答里取出的 HTML 页面,只供当次播放,不入库。回答里没有 HTML 页面时没有 `artifact`。评 `yes_no` 或 `contains` 的自定义题没有 `artifact`。
- `/api/frame` 是静态页,不限速。它由 Worker 返回,`public/_headers` 不作用于它。
- 历史接口一律用 POST,密钥放请求体。对象不存在与对象为空返回相同结果,不泄露对象是否存在。

## 安全边界

接口收得很窄,不是通用代理。

| 调用方能控制 | 不能控制 |
| --- | --- |
| 目标站点(经校验)、自己的密钥、模型名、推理强度、自定义题的题面与评分规则(限长、只评 `yes_no` 与 `contains`、当次即弃) | 请求路径(`/api/models` 固定请求 `GET /v1/models`)、请求体、题库题面(封闭枚举)、返回内容(只回摘要字段) |

| 滥用 | 措施 |
| --- | --- |
| 拿我们撞别家站点的密钥 | 边缘 WAF 限速按 IP 拦截。新对象需首个有效响应才建立 |
| 对某一站点施压 | Worker 内限速绑定按目标主机限流,独立于调用方 IP。持续监测每轮调用同享这个限额 |
| 打内网或元数据地址 | 只允许 `https`,拒绝 IP 字面量与 `localhost`,不跟随重定向,限制响应体与总时长。Worker 子请求本身不能直接发往 IP,且本 Worker 不配置 VPC 绑定,内网不可达(后一点为推断,未单独验证) |
| 灌满限额 | 边缘与 Worker 两层限速,超出返回 429 |
| 灌满存储 | 每轮调用数上限、单次原始数据上限、新对象建立条件、90 天闲置清空 |
| 把本站变成替任何人打任何主机的放大器 | 持续监测有全站 200 个的上限,间隔不低于 1 分钟且每个监测同一时刻只跑一轮,首调 unauthorized 不建立,7 天无人查看自动清空 |

限速分两层,数值均为起点,未实测,上线后调整。

| 层 | 起点 | 说明 |
| --- | --- | --- |
| 边缘 WAF 限速,按 IP,匹配 `/api/probe` 的 POST | 10 秒内 50 次,超出封禁 10 秒,动作为阻止 | `ziikoo.app` 是 Free zone。官方文档中 Free 只有 1 条规则、10 秒窗口、10 秒封禁、仅阻止,按 IP 计数。自定义响应要 Pro 及以上,所以被拦时调用方收到的是 429 加 Cloudflare 默认页面,不是 JSON。这一层只当洪水闸,先于 Worker 生效 |
| Worker 限速绑定,键为调用方 IP | 60 秒内 150 次 | 绑定只支持 10 秒或 60 秒窗口,按节点本地计数,宽松且最终一致,不是精确计数。超出返回 JSON 429 并带 `Retry-After` |
| Worker 限速绑定,键为目标主机名 | 60 秒内 120 次 | 同上。这是保护被测站点的主要手段。原先是 60,但两题满跑约 62 次,几秒内发完,正常用户会撞到本站 429,所以提到 120 |

两题满跑 62 次;每加一题约再加 31 次(ciallo 上线后三题约 93 次,仍在 120 的主机限额内,但已接近,四题同跑会撞本站 429 并按 `Retry-After` 等待)。站点很快时,并发 5 的满跑可能在半分钟内完成,所以 IP 限额不能低于约 100 次每分钟,否则会误伤正常用户。这些数是估计,不是实测,P1 用真实流量校准。

Free 套餐下限速的已知缺口,明确接受:

- 绑定按节点本地计数,分布在多个节点的攻击者拿到的总额度是单节点额度乘以节点数。
- 没有分钟级以上的精确窗口,也没有「同一 IP 单位时间内的不同密钥数」这类需要状态的限制。
- 升级路线有两条,见「升级触发」。

升级触发:出现下列任一情况,就加一个按 IP 与按目标主机分片的限速 Durable Object,获得任意窗口的精确计数。

1. 日志里出现单一目标主机在一分钟内被多个节点同时高频探测。
2. 收到被测站点方的投诉。
3. 对象存储的增长明显快于真实用户数。

另一条路线是把 zone 升到 Pro,换来 60 秒窗口、更长封禁、自定义 JSON 响应和 Super Bot Fight Mode 的跳过规则。这是花钱的选择,由维护者决定,首期不做。

机器人防护:Bot Fight Mode 必须保持关闭。官方文档写明它不能被任何 WAF 规则跳过,会质询匿名脚本,也没有按路径的例外。Free zone 没有 Super Bot Fight Mode。

播放动画:HTML 题 `pelican-svg` 的回答是站点给的 HTML,可能含恶意脚本。本站只在沙箱 iframe 里运行它,规则如下。

1. iframe 只带 `sandbox="allow-scripts"`。它没有 `allow-same-origin`,所以是不透明源,读不到本站的 Cookie、`localStorage` 与页面 DOM。
2. iframe 没有 `allow-popups`、`allow-forms`、`allow-top-navigation`,所以不能开新窗口、提交表单或跳走顶层页面。
3. `/api/frame` 自带 CSP:`default-src 'none'`,只放行内联脚本与样式,以及 `data:`、`blob:` 图片、字体与媒体。CSP 拦住全部网络请求,所以回答不能外传数据,也不能加载外部资源。CSP 另带 `sandbox allow-scripts`,有人直接打开这个地址也同样受限。`frame-ancestors 'self'` 只许本站嵌入它。
4. 宿主页只接受一条消息:来源是父页面、数据是字符串。它用 `document.write` 写入这条消息,之后忽略其他消息。
5. 页面用 `postMessage(artifact.html, "*")` 发送。目标必须写 `"*"`,因为不透明源没有可写的源名。发送的内容是用户自己的回答,不含密钥。

下载 HTML:这份 HTML 不能在本站的源里打开,否则它能读本站的 `localStorage`(看板码)。规则如下。

1. Blob 的类型是 `application/octet-stream`,不是 `text/html`。即使有人打开这个 blob 地址,浏览器也只会下载,不会在本站的源里运行它。
2. 下载链接点击时临时生成,不放进页面,点完立即撤销 blob 地址。
3. 用户在本机打开文件时,页面不在沙箱里,也没有 CSP,可以联网。这和「复制 HTML」后自己打开一样,本站不再加限制。

日志不含任何用户数据。回答原文与原始响应只存在于按密钥访问的对象存储里。每次探针写一条结构化日志,字段只有目标主机名、题 id、结果类别、状态码、延迟,密钥永远不放进请求头或 URL。调用日志(`invocation_logs`)关闭。

出口限制:测试从 Worker 出口发出,区域受限的站点结果可能与用户本机不同,结果卡要说明。

## 失败态映射

| 现象 | 对用户说什么 | 下一步 |
| --- | --- | --- |
| 401 | 密钥无效或模型无权限 | 检查密钥 |
| 403 或拦截页 | 站点拒绝了来自服务器的请求 | 联系站点,或换网络自测 |
| 404 | 地址或通道不对 | 检查是否多填了路径 |
| 429 | 站点正忙或限流 | 几分钟后再测 |
| 502、503 | 站点推理接口不可用 | 等恢复后重测 |
| 超时 | 站点响应太慢 | 稍后重测 |
| 空答案或非 JSON | 站点返回异常 | 若该站点与密钥此前已有历史,在历史里下载原始数据查看;否则在本机用 curl 自测该地址。失败调用不会建立新对象,首轮失败没有历史可下载 |

## 解析细节(来自脚本经验)

- 需要浏览器 User-Agent,部分站前置 Cloudflare 会拦默认 UA。
- 响应体含 `"error": null` 是正常的,`error` 非 null 才算报错。
- JSON 宽容解析,允许未转义控制字符。
- SSL 瞬断偶发,重试即可,不算站点故障。
- reasoning tokens 与响应 ID 形态要展示:答 No 的调用 reasoning tokens 往往明显偏低,这是用户能看到的「为什么」。
- 流式读取时同时计字节和计时,超过上限就中断并标记被截断,不要对不受控数据 `await response.text()`。

- 地址校验的拒绝用例。
- 脱敏:站点响应里回显了密钥时,入库的文本不含密钥。
- 保留最近 10 轮:写入第 11 轮后最旧一轮被删除。
- 对象标识:同一站点的不同写法(大小写、尾部 `/v1`)得到同一标识,不同密钥得到不同标识。
- 校准检查(P1 验收):用一个已知通过和一个已知不通过的站点各跑一轮糖果,人工核对没有「正确却被判错」。需要真实密钥,由维护者提供。
